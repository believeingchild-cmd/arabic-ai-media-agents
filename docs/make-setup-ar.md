# ربط Make بالمشروع (عربي)

## الوضع الآمن الحالي
- نقطة الاستقبال تحفظ طلبًا في طابور محلي ولا تنفذ أوامر ولا تنشر تلقائيًا.
- الاستقبال مربوط افتراضيًا بـ `127.0.0.1:8787` ومحمٍ بمفتاح `x-make-apikey`.
- لا تفتح المنفذ للإنترنت مباشرة. لا تستخدم عنوان localhost من Make السحابي؛ فهو يشير إلى خوادم Make لا جهازك. للوصول عن بعد، انشر الخدمة خلف HTTPS ومصادقة على خادم موثوق، أو استخدم عاملًا محليًا يسحب المهام من خدمة آمنة.
- لا تضع أي مفاتيح داخل Git أو رسائل السيناريو.

## تشغيل نقطة الاستقبال محليًا
Windows PowerShell:
```powershell
$env:MAKE_WEBHOOK_API_KEY = "ضع-هنا-سرًا-عشوائيًا-طويلًا-لا-يقل-عن-32-حرفًا"
python integrations/make_webhook.py
```

macOS/Linux:
```bash
export MAKE_WEBHOOK_API_KEY='ضع-هنا-سرًا-عشوائيًا-طويلًا-لا-يقل-عن-32-حرفًا'
python integrations/make_webhook.py
```

## طلب الاختبار
```bash
curl -X POST http://127.0.0.1:8787/v1/jobs \
  -H 'Content-Type: application/json' \
  -H 'x-make-apikey: YOUR_LONG_SECRET' \
  -d '{"request_id":"test-job-0001","channel":"children","topic":"آداب الاستئذان للأطفال"}'
```
الاستجابة المتوقعة `202 queued_for_review`. الطلبات المكررة بنفس `request_id` لا تنشئ مهمة ثانية.

## سيناريو Make المقترح
1. Scheduler: ثلاثة مواعيد أسبوعية لقناة الأطفال وثلاثة مستقلة للقناة العامة.
2. Set variables: أنشئ `request_id` فريدًا لكل مهمة، وحدد `channel` و`topic`.
3. HTTP: أرسل JSON إلى عنوان خدمة HTTPS المنشورة لديك، مع `x-make-apikey` في خانة الأسرار.
4. عند نجاح الاستجابة: سجّل المهمة وأرسل إشعارًا.
5. لا تضف خطوة نشر مباشرة من Make. يجب أن تمر المهمة بالتوليد، وفحص الفيديو، وبوابة الجودة، ومراجعة التحرير. يبدأ النشر الخاص/التجريبي أولًا.

## ملاحظات المنصات
- YouTube: يلزم إعداد OAuth وصلاحيات القناة.
- Instagram: يلزم حساب احترافي ومتطلبات Meta API.
- TikTok: النشر العام عبر API يعتمد على موافقة التطبيق والصلاحيات ومراجعة TikTok؛ لا تفترض أن حسابًا جديدًا يستطيع النشر العام آليًا.
